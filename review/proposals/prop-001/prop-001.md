## Summary

**Material decisions in the draft** (each made only to resolve a demonstrated defect):
1. **The check takes the prompt it answers** (`sdd check <skeleton> <prompt> <paste>`). Batch, round and slot set
   come from the prompt, which makes provenance and repair rounds derivable (F26, F28).
2. **A repair asks for the complete corrected set** for the batch, not only the failed lines. That keeps one
   validated report per batch and makes merging trivial (F26).
3. **Messages are generated by the core** from fixed templates, so every screen text is artifact-grounded (F32).
4. **A PromptSet artifact** (JSON-LD) summarises a multi-batch prompt run. It is the minimum needed for the CLI to
   emit several prompts and their warnings (F31, F39). This is the only new artifact type.
5. **Citations are explicit identifiers** and the tables are generated, which makes reciprocity mechanically checkable (F27).

**Scope:** no new capabilities, no new infrastructure, the same seven capabilities. The additions are 1 artifact
type (PromptSet), 1 test harness module (the network guard), new error and warning codes, and 4 fixtures. Witness
files v1 superseded: `prompt.txt`, `check-report.jsonld`, `bad-check-report.jsonld` (retained under
`superseded/v1/` on merge).

**Decisions needed from the registrar:**
- **A. ADR-004.1 wording (F45).** It says the prompt carries the output format "as a JSON Schema". The draft carries
  an example object and applies the JSON Schema inside C-S4 (OS-1). Recommendation: amend ADR-004.1 to match, since a
  schema in every prompt adds tokens without strengthening any check. The alternative is to embed the schema in
  template v3.
- **B. OS-5, `time` values,** remains open (text fallback).

**Unresolved after merge (named at the gate, not orphans):** W-CS4-Δ5's literal (OS-2: domain/range in the term
list); the reciprocity demonstration (OS-7); nothing built or executed (OS-4, OO-1). **CAP-2 remains active**, so the
best joint disposition cycle 3 could record is **D-2**, until OS-7 runs.
